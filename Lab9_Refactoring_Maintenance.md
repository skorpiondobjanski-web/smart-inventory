## ПОРЯДОК І ЗМІСТ ВИКОНАННЯ ЗАВДАНЬ

### ЗАВДАННЯ 1. АНАЛІЗ ТЕХНІЧНОГО БОРГУ ТА МЕТРИК ЯКОСТІ КОДУ

У процесі тривалої розробки або швидкого випуску фіч у системі SmartInventory накопичується **технічний борг** — компромісні, неоптимальні рішення у коді, які ускладнюють його подальший супровід та розширення.

Для оцінки якості коду було проведено аудит за допомогою двох основних метрик:
1. **Цикломатична складність (Cyclomatic Complexity):** Кількість лінійно незалежних шляхів через вихідний код програми. Висока цикломатична складність (понад 10–15 на одну функцію) свідчить про наявність великої кількості вкладених умов `if/else` або циклів, що ускладнює розуміння коду та написання тестів.
2. **Когнітивна складність (Cognitive Complexity):** Метрика, що оцінює, наскільки важко людині зрозуміти логіку коду при читанні. Вона враховує вкладеність конструкцій та порушення лінійного потоку сприйняття.

### ЗАВДАННЯ 2. РЕФАКТОРИНГ ПРОБЛЕМНОЇ ДІЛЯНКИ КОДУ (LEGACY CODE)

Під час аудиту було виявлено «запах коду» **«Довгий метод» (Long Method)** та **«Складні розгалуження» (Nested Conditionals)** у модулі обробки складських накладних.

#### 2.1. Проблемний вихідний код (до рефакторингу):
Метод `processDocument` мав занадто високу цикломатичну складність (= 14) та виконував занадто багато обов'язків (валідація, розрахунки, оновлення бази даних, сповіщення):

```javascript
// Legacy Code
class DocumentService {
  processDocument(doc) {
    if (doc !== null && doc !== undefined) {
      if (doc.items.length > 0) {
        if (doc.type === 'INFLOW') {
          for (let i = 0; i < doc.items.length; i++) {
            let item = doc.items[i];
            if (item.quantity > 0 && item.price >= 0) {
              // Логіка оприбуткування
              console.log("Оприбуткування товару: " + item.productId);
              db.saveStock(doc.warehouseId, item.productId, item.quantity);
            } else {
              throw new Error("Невірна кількість або ціна!");
            }
          }
          doc.status = 'PROCESSED';
        } else if (doc.type === 'OUTFLOW') {
          for (let i = 0; i < doc.items.length; i++) {
            let item = doc.items[i];
            let currentStock = db.getStock(doc.warehouseId, item.productId);
            if (currentStock >= item.quantity) {
              // Логіка FIFO списання собівартості...
              db.decreaseStock(doc.warehouseId, item.productId, item.quantity);
              // Перевірка лімітів дефіциту
              let safety = db.getSafetyStock(item.productId);
              if (currentStock - item.quantity < safety) {
                console.log("Увага: низький запас!");
                notifier.sendAlert(item.productId);
              }
            } else {
              throw new Error("Недостатній залишок!");
            }
          }
          doc.status = 'PROCESSED';
        }
      } else {
        throw new Error("Документ порожній!");
      }
    } else {
      throw new Error("Документ не існує!");
    }
  }
}
```

#### 2.2. Застосовані патерни рефакторингу:
1. **Виділення методу (Extract Method):** Окремі блоки логіки для приходу, витрати та перевірки залишків виділено у незалежні, малі та перевикористовувані методи.
2. **Заміна умовних конструкцій поліморфізмом або стратегіями (Replace Conditional with Strategy):** Логіку обробки різних типів накладних перенесено у спеціалізовані класи-обробники.
3. **Захисні твердження (Guard Clauses):** Заміна глибоко вкладених `if` на швидке повернення помилок на початку методу для покращення читабельності коду.

### ЗАВДАННЯ 3. ЧИСТИЙ КОД ПІСЛЯ РЕФАКТОРИНГУ

Після проведення рефакторингу цикломатична складність головного методу зменшилася до **2**, код став чистим, легко тестується та відповідає принципу **Single Responsibility Principle (SRP)** з SOLID.

```javascript
// Clean Code
class DocumentService {
  constructor(validators, processors, alertService) {
    this.validators = validators;
    this.processors = processors; // Об'єкт, що містить обробники INFLOW та OUTFLOW
    this.alertService = alertService;
  }

  processDocument(doc) {
    // 1. Guard clauses (Захисні твердження)
    this.validateDocumentPresence(doc);
    
    // 2. Вибір процесора відповідно до типу документа (Поліморфізм/Стратегія)
    const processor = this.processors[doc.type];
    if (!processor) {
      throw new Error(`Невідомий тип документа: ${doc.type}`);
    }

    // 3. Обробка та проведення
    processor.execute(doc);
    doc.status = 'PROCESSED';
    
    // 4. Попередня перевірка залишків
    this.alertService.checkWarehouseAlerts(doc);
  }

  validateDocumentPresence(doc) {
    if (!doc) {
      throw new Error("Документ не існує!");
    }
    if (!doc.items || doc.items.length === 0) {
      
      throw new Error("Документ порожній!");
    }
  }
}
```

### ЗАВДАННЯ 4. СТВОРЕННЯ BUG REPORT (ЗВІТУ ПРО ПОМИЛКУ) ДЛЯ СУПРОВОДУ ПЗ

У процесі експлуатації та супроводу системи «SmartInventory» було виявлено дефект, пов'язаний з некоректним відображенням звітів собівартості FIFO. Складено та зареєстровано офіційний **Bug Report** у системі трекінгу задач (Jira/GitLab).

#### Bug Report #BUG-1048: Помилка розрахунку FIFO при злитті нульових партій

* **Назва багу (Summary):** `Помилка NaN при генерації відомості собівартості FIFO для товарів без проведених транзакцій`
* **Опис дефекту (Description):** При відкритті звіту «Оборотно-сальдова відомість собівартості» для нових товарних позицій, по яких не було проведено жодної прихідної накладної, колонка «Початкова балансова вартість» відображає значення `NaN` замість `0.00 грн`. Це порушує звітність та призводить до збоїв при спробі експорту звіту в Excel.
* **Крок 1 (Steps to Reproduce):**
  1. Створити нову картку товару «Кулер Noctua NH-D15» без початкових залишків.
  2. Перейти в розділ «Аналітика» -> «Звіти собівартості FIFO».
  3. Сформувати відомість за поточний місяць.
* **Очікуваний результат (Expected Result):** У рядку товару «Кулер Noctua NH-D15» у колонці «Собівартість» відображається `0.00 грн`.
* **Фактичний результат (Actual Result):** Відображається значення `NaN` (Not a Number). При натисканні «Експорт в XLSX» сервер повертає помилку 500.
* **Пріоритет (Priority):** **High** (Високий). Заважає формуванню звітності.
* **Критичність (Severity):** **Major** (Значний). Порушує роботу окремого функціонального модуля (експорт звітів).
* **Оточення (Environment):** Ubuntu Server 22.04 LTS, Node.js 18.15.0, Google Chrome v121.
