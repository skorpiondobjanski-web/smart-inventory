## ПОРЯДОК І ЗМІСТ ВИКОНАННЯ ЗАВДАНЬ

### ЗАВДАННЯ 1. СТВОРЕННЯ ТЕСТ-ПЛАНУ (TEST PLAN)

#### 1.1. Об'єкт тестування
Об'єктом тестування є веб-система управління запасами «SmartInventory» версії 1.0, яка включає клієнтський інтерфейс (Frontend React.js), серверний API (Backend NestJS) та базу даних PostgreSQL.

#### 1.2. Стратегія тестування
Тестування проводиться за принципом **«Чорної скриньки» (Black Box Testing)** для функціональної валідації та **«Білої скриньки» (White Box / Unit Testing)** для автоматичної верифікації розрахункових алгоритмів собівартості.

Рівні тестування:
* **Модульне (Unit Testing):** автоматична перевірка окремих ізольованих функцій бізнес-логіки (розрахунки FIFO, правила валідації полів).
* **Інтеграційне (Integration Testing):** перевірка взаємодії складського API з PostgreSQL та Redis.
* **Системне/Функціональне (System Testing):** ручна перевірка відповідності інтерфейсу користувача та документообігу вимогам ТЗ.

#### 1.3. Критерії початку та завершення тестування
* **Критерії початку:**
  * Готовий та успішно зібраний білд системи SmartInventory без синтаксичних помилок.
  * Розгорнута тестова база даних PostgreSQL із заповненими тестовими даними (seeds).
  * Затверджене Технічне завдання (ТЗ) та Специфікація вимог (SRS).
* **Критерії завершення:**
  * 100% запланованих тест-кейсів виконано.
  * Відсоток успішно пройдених тестів (Pass Rate) становить >= 95%.
  * Усі критичні дефекти (блоки типу Crash, Block, Critical bug) виправлені та верифіковані.
  * Покриття коду автоматизованими юніт-тестами (Code Coverage) бізнес-рівня становить >= 80%.

### ЗАВДАННЯ 2. РОЗРОБКА ТЕСТ-КЕЙСІВ (TEST CASES)

Для верифікації ключових функцій системи було розроблено наступні тестові сценарії:

#### Тест-кейс TC-001: Авторизація користувача з різними правами
* **Функція:** Модуль автентифікації та рольової моделі (RBAC).
* **Крок 1:** Перехід на сторінку `/login`, введення логіну `storekeeper@company.com` та паролю `correct_pwd`, натискання «Увійти».
  * *Очікуваний результат:* Авторизація успішна. Перенаправлення на `/dashboard`. Меню «Звіти собівартості» та «Адміністрування» є прихованими.
* **Крок 2:** Вихід із системи. Введення логіну `admin@company.com` та невірного паролю.
  * *Очікуваний результат:* Авторизація заблокована. Червоне повідомлення: *«Невірний логін або пароль»*. Токен доступу не створений.

#### Тест-кейс TC-002: Створення картки товару з коректною валідацією
* **Функція:** Модуль ведення каталогу.
* **Крок 1:** Перехід до розділу «Товари», натискання «Додати товар». Залишення обов'язкового поля «Артикул (SKU)» порожнім. Натискання «Зберегти».
  * *Очікуваний результат:* Запис заблоковано. Поле «Артикул» підсвічується червоним із текстом: *«Артикул є обов'язковим для заповнення»*.
* **Крок 2:** Введення існуючого в системі артикулу `SKU-10025`, заповнення інших полів, натискання «Зберегти».
  * *Очікуваний результат:* Запис заблоковано. Помилка: *«Товар з таким артикулом уже існує»*.

#### Тест-кейс TC-003: Контроль критичного залишку (Low-Stock Notification)
* **Функція:** Модуль автоматичних сповіщень.
* **Крок 1:** Створення картки товару з параметром `safety_stock = 10` та початковим залишком 15 одиниць.
* **Крок 2:** Створення та проведення видаткової накладної на списання 7 одиниць цього товару.
  * *Очікуваний результат:* Новий залишок становить 8 одиниць. На панелі приладів (Dashboard) з'являється червоний попереджувальний значок дефіциту біля цього товару. Відповідальному менеджеру надходить E-mail/Telegram сповіщення.

### ЗАВДАННЯ 3. АВТОМАТИЗОВАНЕ ЮНІТ-ТЕСТУВАННЯ (UNIT TESTING)

Для перевірки математичної та логічної коректності розрахунку собівартості списання запасів за методом **FIFO (First In, First Out)** було написано автоматизований тест на мові JavaScript/TypeScript з використанням фреймворку Jest.

#### Логіка тесту:
* Партія 1: 10 одиниць товару закуплено за ціною 100 грн.
* Партія 2: 5 одиниць товару закуплено за ціною 120 грн.
* Запит на списання: списати 12 одиниць товару.
* Розрахунок собівартості FIFO:
  * Перші 10 одиниць мають бути списані за ціною 100 грн (всього 1000 грн).
  * Наступні 2 одиниці мають бути списані з Партії 2 за ціною 120 грн (всього 240 грн).
  * Загальна собівартість списання має становити: **1240 грн**.

#### Вихідний код автоматизованого тесту (`fifo.test.js`):
```javascript
// Функція розрахунку собівартості списання партії товару за методом FIFO
function calculateFIFOCost(batches, qtyToWithdraw) {
  let totalCost = 0;
  let remainingQty = qtyToWithdraw;

  // Копіюємо масив партій для безпечної роботи без мутацій
  let tempBatches = JSON.parse(JSON.stringify(batches));

  for (let batch of tempBatches) {
    if (remainingQty <= 0) break;

    if (batch.quantity >= remainingQty) {
      // Якщо в партії достатньо товару для покриття всього залишку списання
      totalCost += remainingQty * batch.price;
      batch.quantity -= remainingQty;
      remainingQty = 0;
    } else {
      // Якщо партія покриває залишок лише частково
      totalCost += batch.quantity * batch.price;
      remainingQty -= batch.quantity;
      batch.quantity = 0;
    }
  }

  if (remainingQty > 0) {
    throw new Error("Недостатній загальний залишок товару на складах для списання!");
  }

  return totalCost;
}

// Набір тестів Jest
describe("Тестування алгоритму собівартості FIFO в системі SmartInventory", () => {
  
  test("Успішний розрахунок собівартості списання з двох різних партій (FIFO)", () => {
    // Вхідні дані: наявні партії товару на складі
    const activeBatches = [
      { id: "batch-1", quantity: 10, price: 100.00 }, // Надійшла першою
      { id: "batch-2", quantity: 5,  price: 120.00 }  // Надійшла другою
    ];

    const qtyToWithdraw = 12; // Запит на продаж 12 одиниць
    const expectedCost = (10 * 100.00) + (2 * 120.00); // 1000 + 240 = 1240.00

    const actualCost = calculateFIFOCost(activeBatches, qtyToWithdraw);
    
    // Перевірка відповідності очікуваного та фактичного значень
    expect(actualCost).toBe(expectedCost);
    expect(actualCost).toBe(1240.00);
  });

  test("Викид помилки при спробі списати більше товару, ніж є в усіх партіях разом", () => {
    const activeBatches = [
      { id: "batch-1", quantity: 5, price: 50.00 }
    ];
    
    // Спроба списати 8 одиниць при наявності лише 5
    expect(() => {
      calculateFIFOCost(activeBatches, 8);
    }).toThrow("Недостатній загальний залишок товару на складах для списання!");
  });
});
```
